## How this audit was run

1. **Round 1, broad scan.** Five read-only reviewers (architecture, security, performance, code quality, data layer) scanned the whole tree.
2. **Round 2, deep dive.** The same specialists re-read the hotspots and checked each Round 1 claim against the code, confirming or rejecting it. Each finding was then classed as a **safe-fix** (non-breaking and mechanical) or a **proposal** (a change in behaviour or architecture, reported only). In case of doubt, it went to proposals.
3. **Round 3, apply.** Safe fixes were applied on the branch, each behavioural fix with a regression test.
   - Every new regression test was run against the code without its fix: all of them fail there and pass on the branch.
   - No safe fix had to be reverted or downgraded.
4. **Commit review.** Background security reviews ran on the commits.
   - The first flagged two residual issues, in `routes/envVars.ts` and `traefikLabels.ts`.
   - A second review of that fix found three ways around it: a key containing `=`, Unicode case folding, and a non-boolean `sensitive` flag.
   - All were fixed with tests; they are the last two rows of the Security table below.

**Top 5 open items by impact:**

1. **The image manifest rewrites the global app definition.** Anyone who can push a tag to an app's registry controls services, volumes, `env_mapping`, `admin_access` and middlewares for every tenant of that app (`tenant.ts:456-484` → `app.ts applyApp`).
2. **Tenant create can drop a database it did not create.** `createDatabase` uses `IF NOT EXISTS` and adopts a pre-existing database, and a later rollback then drops it (`tenant.ts:177-257`, `mysql.ts:48-50`, `postgres.ts:50-69`).
3. **Backups and restores report success when they are incomplete.** In addition, a restore for a migrated tenant goes into the wrong database: it uses `${appId}_${tenantId}` instead of the tenant's `DB_NAME` (`backup.ts:293,321,500,518`).
4. **`overwatch init` followed by `overwatch infra deploy` downgrades MariaDB 11 to 10.11** on the same data volume, renames the Let's Encrypt volume, and mounts `overwatch.yaml` read-only, which breaks Traefik edits from the UI (`cli/init.ts` vs `infraComposeGenerator.ts` vs the templates).
5. **Backup schedules are only registered at boot.** New apps get no scheduled backups until a restart, schedule edits are ignored, and deleted apps keep firing (`scheduler.ts`).

## PROPOSALS

These are report-only, for triage over time. Within each group they are sorted by impact against effort.

### Security

**High**

- **The image manifest is trusted with the global app definition.**
  - Files: `services/tenant.ts:456-484`, `manifestExtractor.ts`, `app.ts:239-289`.
  - Risk: a tenant update applies `/overwatch/app.json` from the pulled image to `apps.d/<id>.json`, the definition shared by all tenants.
  - Fix: apply it only to the per-tenant snapshot (`writeTenantAppDef`). Alternatively, allowlist the fields a manifest may change (e.g. env_var declarations, ports, health_check) and require admin approval for volumes, user, command, networks, `admin_access`, `db_prefix`, `raw_labels` and backup.
- **Compose YAML is still built from strings.**
  - Files: `composeGenerator.ts:75-196`, `traefikLabels.ts:55-59`.
  - The line-break fix above removes structural break-out. But `push()` still doesn't escape `\`, so `\"` closes the quoted value early, and `composeGenerator` writes `service.name`, `env_mapping` keys, volume names and paths, `hc.path`, `interval` and `depends_on` unescaped.
  - Fix: build the compose file as an object and serialise it with `js-yaml` `dump`, as `infraComposeGenerator` already does. Before shipping, test a `redirectRegex` fixture for double escaping.
- **Hostname hijack through `host_aliases`.**
  - Files: `traefikLabels.ts:60-64`, `models/traefik.ts:304`.
  - Risk: an editor can claim the admin host or another tenant's FQDN, and the longer rule wins Traefik's priority.
  - Fix: validate aliases against `domain_template` and an operator allowlist. Reject the Overwatch host and domains owned by other tenants.
- **Compose `${VAR}` interpolation resolves against Overwatch's own environment.**
  - Files: `composeGenerator.ts:~296`; compose `execFile` calls in `tenant.ts` and `docker.ts` inherit `process.env`.
  - Risk: `env_mapping: {X: "MYSQL_ROOT_PASSWORD"}` hands Overwatch's secrets to a tenant container.
  - Fix: run compose with a curated environment, as `backup.ts:53-63` already does, and reject `env_mapping` names that collide with core secrets.

**Medium**

- **`admin_access.secret_env` can name `JWT_SECRET`** (`routes/tenants.ts:116-145`).
  - Risk: tenant-admin tokens would then be signed with Overwatch's session key.
  - Fix: reject reserved names at mint time and warn on load. A schema refine would fail boot for existing definitions.
- **MCP OAuth allows open dynamic client registration with no consent screen** (`routes/oauth.ts:83-167`).
  - Fix: add a consent interstitial that names the client and redirect host, require https or loopback `redirect_uris`, cap registrations, and prune `oauth/store.ts`.
- **RBAC roles can't be assigned from any surface** (`users.ts:112-133`, `routes/adminUsers.ts`, CLI, UI).
  - Risk: every user added becomes a full admin.
  - Fix: require a role on add (default `viewer`) and add a role-edit endpoint and UI.
- **App Settings can't disable backup or admin access** (`AppSettingsPage.tsx:45-46`, plus the shallow merge in `app.ts:216`).
  - Risk: unchecking "Admin access" leaves token minting on, and the UI still reports success.
  - Fix: send the disabled block and parse `PUT /apps/:id` with `UpdateAppSchema` at the route.
- **Postgres tenants can connect to each other's databases** (`postgres.ts:50-74`).
  - Fix: `REVOKE CONNECT ... FROM PUBLIC`, then grant it to the tenant role only.
- **The DB root password appears in `docker exec` argv** (`mysql.ts:106,135`, `postgres.ts:135,163`), and the comments there claim otherwise.
  - Fix: pass `-e MYSQL_PWD` by name only, with the value in the child process environment.
- **5xx responses echo `err.message`** (`index.ts` global handler).
  - Risk: file paths and compose/DB internals reach clients.
  - Fix: add `HttpError` classes with an explicit "expose" flag and return a generic message for other 5xx errors.

**Low**

- **The `raw_labels` schema still accepts reserved keys hidden by letter case, `=`, a backslash or non-ASCII characters, and the denylist has no `traefik.tcp.*`/`udp.*` entries** (`models/traefik.ts:131-137`). Emit-time filtering now drops those keys. Rejecting them at save time needs a load-time warn-and-strip path first, because the schema is parsed at boot. Add tcp/udp entries only after confirming nobody relies on L4 routing through the escape hatch.
- **WebSocket auth is point-in-time** (`websocket/server.ts`).
  - Problem: there is no `isAdminEmail` check at handshake and no close at token expiry. `close` and `error` both untrack the connection, so the per-user count is decremented twice.
- **There are three SSRF guards with different rules**: `routes/monitoring.ts`, `notifications/webhook.ts` and `adapters/registry/urlValidation.ts`.
  - `OVERWATCH_ALLOW_PRIVATE_WEBHOOK` is honoured at save but not at send.
  - The registry guard checks IPv4 only and doesn't use `redirect: 'manual'`.
  - Fix: one `utils/ssrf.ts`.
- **`/api/monitoring` mutations are not audited.** Add `auditLog` together with URL redaction in `sanitizeValue`; otherwise webhook secrets would land in `audit.log`.
- **Session JWTs have no `aud`/`iss`.** This is hardening only: cross-replay with MCP tokens was checked and is not possible today.
- **First-party GitHub Actions are not SHA-pinned** (`build.yml`, `codeql.yml`, `cleanup-ghcr.yml`). The third-party actions already are.
- **Viewers get full SQL text** from the DB process list and htpasswd hashes from `GET /api/traefik/middlewares`.

### Architecture

- **[high×low] The infra compose file has three to four sources that disagree:** `cli/init.ts:382-565`, `templates/infrastructure/docker-compose.yml`, `infraComposeGenerator.ts` and `docs/deployment.md`.
  - Fix: make `infraComposeGenerator` the single source and have `init` call it. Add a MariaDB downgrade guard to `deployInfra`, and decide the MariaDB version once (10.11 → 11 needs `MARIADB_AUTO_UPGRADE=1`).
- **[high×med] UI types are hand-copied from the Zod schemas** (`ui/src/lib/types.ts`). That drift caused two of the bugs fixed here.
  - Fix: generate the UI types from the schemas (like `embed-templates`) with a CI drift check, or add a contract test.
- **[med×med] `overwatch.yaml` has four writers with different safety:** `traefikConfig.ts` (locked, `copyFile`), `cli/config/traefik.ts` (`rename`, which swaps the inode of a single-file bind mount and strands the container's view), `cli/config/edit.ts` and `migration.ts`.
  - Fix: one `config/writer.ts` with a lock, validation and a copy-in-place write.
- **[med×low] There are no typed domain errors.** Validation and not-found errors become 500, and `PUT /apps/:id` has no route-level parse.
  - Fix: `utils/httpErrors.ts` mapped once for REST and once for MCP.
- **[med×low] Auth logic is spread out.** Session JWT verification exists four times and the Google→admin flow twice, and each request verifies the JWT three times.
  - Fix: `auth/session.ts` with `res.locals.user`.
- **[med×med] Business workflows live in routes:** create-tenant-from-backup (a fixed 5 s sleep and no rollback) and admin-access token minting.
  - Fix: move them to `services/backup.createTenantFromBackup()` and `services/adminAccess.ts`.
- **[med×low] Nobody owns the audit log.** The writer lives in Express middleware and is imported by the CLI and MCP, the reader duplicates `AuditEntry`, and retention races the writer.
  - Fix: a `services/auditLog.ts` that owns path, append, read and prune.
- **[med×low] Knowledge of the tenant directory layout is scattered**: `path.join(appsDir, appId, 'tenants', tenantId)` appears about 8 times, and so does the tenant-directory walk.
  - Fix: `services/tenantStore.ts`.
- **[med×low] The data-file lists are maintained by hand.** The snapshot list misses `notification-channels.json` and `mcp-oauth.json` (`configSnapshots.ts:6-14`).
  - Fix: a `config/dataFiles.ts` registry.
- **[low×med] The event bus is untyped**, and the domain layer imports transport types (`tenant.ts` → `websocket/types`).
- **[low×med] The registry and service forms are duplicated** between the wizard and Settings, and Settings is missing `tag_pattern`.
- **[low×med] Tests are organised by delivery batch** (sprint1-6, remaining-review-fixes, safe-fixes) rather than by module, and the UI has no tests. The new tests in this branch are per module.
- **[low×low] Import cycle between `backup.ts` and `backupCache.ts`.** It is harmless at runtime; break it with a `backupCacheStore.ts`.
- **[low×low] `cli/lifecycle.ts:189` hardcodes `overwatch/data`.** Use `getDataDir()` with a fallback.

### Cost & performance

- **[high×low-med] `listTenants` is N+1** (`docker.ts:181-245`).
  - Problem: every tenant triggers a full `docker.listContainers` plus an `apps.d` re-read. The UI polls it every 30 s, and MCP and `backupAllTenants` call it too.
  - Fix: list the containers once and group them by `appId:tenantId`, keeping the per-tenant error semantics.
- **[high×med] `readApps()` is uncached.** It runs on every request and on the 10 s and 15 s timers.
  - Fix: a cache keyed on mtime, size and inode. Don't cache errors, and keep the runtime-synthesis write.
- **[med×low] UI polling duplicates the WebSocket push.**
  - Polled today: tenants every 30 s, health every 30 s, metrics every 15 s (the same cadence as the WS), DB processes every 5 s, and logs every 10 s at up to 10 000 lines.
  - Fix: while the WS is connected, drop the intervals and `setQueryData` from WS messages.
- **[med×low] `/api/status/health` makes four serial awaits** and reads the apps twice. `findManagedContainerId` lists every container to validate one id on each logs or restart call.
- **[med×med] Health checks run serially**, so each hung check stalls the cycle for 5 s.
  - Fix: `Promise.allSettled` with a concurrency cap, emitting the events in order.
- **[low-med×low] The UI has no code splitting**: it ships one 475 KB (131 KB gzip) JS chunk.
  - Fix: `React.lazy` for Monitoring, Backups, Database, Traefik and the wizard.
- **[low×low] `extractContainerInfoFromKnownApps` re-sorts apps and services for every container.** Hoist the sort out of the loop.
- **[low×low] WebSocket broadcasts have no `bufferedAmount` backpressure.**
- **[low×low] DB pools have no connect or statement timeouts** (the pg default is infinite) and are not closed on shutdown.
- **[low×low] The Dockerfile installs `curl`, which Overwatch itself doesn't use.** The pkg target is node20 while the image runs node26.
- **[low×low] Monitoring maps are never evicted** (`metricsHistory`, `healthStates`, the `alertEngine` maps). Evict on a TTL with resolve-before-evict semantics; see Cleanup & quality.

### Cleanup & quality (incl. correctness)

- **[high×low] Backup schedulers are only built at boot** (`scheduler.ts`).
  - Fix: `reconcileBackupSchedulers()` called after each app mutation and on a short cron, since CLI `apps.d` edits bypass the server.
- **[high×med] Tenant create can drop a database it adopted** (`tenant.ts:177-257`, `mysql.ts:44-60`, `postgres.ts:36-72`).
  - Problem: `createDatabase` adopts a pre-existing database or user, and the rollback then drops it. A partial create leaks objects.
  - Fix: return `{created}`, add a pre-flight existence check, and compensate within `createDatabase`.
- **[high×low] Backup and restore integrity** (`backup.ts:293,321-323,500,518-531`).
  - Problem: an `exec ls` failure is treated as an empty directory and not marked incomplete, and restore swallows path failures. Both use `${appId}_${tenantId}` instead of the tenant's `DB_NAME`.
  - Fix: a `resolveTenantDbId()` helper shared with `deleteTenant`.
- **[med×low] Webhook delivery failures are reported as success.** `sendWebhook` swallows the final error, so `/notifications/:id/test` returns success, and alert dispatch uses `.catch(() => {})`.
- **[med×low] The retention prune races the audit and alert appends**, so entries are lost (`retention.ts`). Take a shared lock, or route the prune through the audit queue.
- **[med×low] Docker events are parsed one chunk at a time**, so merged events are lost and produce false `container_down` alerts. The app pattern is built once per connection, so new apps get no events.
  - Fix: buffer lines, and filter on the `com.overwatch.managed` label.
- **[med×low] Alert-engine edge cases.**
  - `container_down` timeouts are untracked, so die→start→die fires early.
  - The engine's listeners are not removed on stop.
  - Removed containers stay in `/api/monitoring` forever.
- **[med×low] `regenerateAllSharedEnvFiles` swallows write errors**, so an env-var save reports success while `shared.env` stays stale.
- **[med×med] Tenant compose and restic shell-outs have no timeout, no `maxBuffer` and no per-tenant lock.** Once `restic snapshots` output exceeds 1 MB, `listSnapshots` returns `[]` and caches it for 10 minutes.
- **[low×low] A corrupt `notification-channels.json` is read as `[]`** and overwritten on the next save. Use the `readJsonStrict` pattern.
- **[low×med] Writes on rollback paths are not atomic** (`tenant.ts:436,511`).
  - Fix: a shared `writeFileAtomic`. Don't use it for files that are bind-mounted individually.
- **[low×low] The trash/restore API has no UI or CLI caller**, and the `applyApp` error message points to `overwatch apps restore|purge`, which don't exist. The `useTrashedApps`/`useRestoreApp` hooks were kept: either build the view or remove them.
- **[low×low] The build gate is weak in three places.**
  - Tests are never type-checked: `tsconfig` excludes `__tests__`.
  - The server has no `noUnusedLocals`.
  - CI doesn't fail on `src/generated` drift.
  - The Node versions are split: Docker 26, CI 22, pkg 20.
- **[low×low] The docs lag the code.**
  - The `architecture.md` file tree is missing about 50 files (`mcp/`, `oauth/`, …).
  - `OVERWATCH_ALLOW_PRIVATE_WEBHOOK`, `OVERWATCH_SKIP_CHECKSUM` and `data_dir` are undocumented.
- **[low×low] `scripts/update.sh` and `tenant-template/` are unreferenced.** Operators may have copied `update.sh`, so confirm before deleting.
- **[low×low] Trivial tidy-up:** the `scheduler.ts` stop loop, and the `routes/tenants.ts` `appId ? … : all` branch, which is always true.
